# ADR-001: Project Structure — Two Independent Projects

**Status:** Accepted

## Context

The platform consists of two distinct components with no shared code:
1. A Flutter Android app (student client) — widget-based UI, SQLite local storage, Dart
2. A FastAPI Python server (hub/teacher portal) — REST API, SQLite server DB, HTML dashboard

Previously these lived in a single conceptual repo with no clear boundary,
making it ambiguous where concerns belonged.

## Decision

Separate the projects into independent directories under the workspace root:
- `EduMesh-Android/` — Flutter app (no cross-references to server code)
- `Debian Server/` — FastAPI server (no cross-references to app code)

Each project has its own dependency file (`pubspec.yaml` / `requirements.txt`),
its own toolchain (`flutter` / `python`), and its own test suite.

## Consequences

- **Positive:** Clear ownership; changes to one project never risk breaking the other
- **Positive:** CI can run Flutter and Python checks independently
- **Positive:** Different contributor skill sets can work in parallel
- **Negative:** Shared types (e.g., resource model) must be duplicated or versioned
- **Neutral:** The workspace root serves only as a container; no shared build step
